# flac benchmarks

[xiph/flac](https://github.com/xiph/flac) CLI, built BOLT-ready.

## Inputs

Generated by `bench/flac/setup.sh` (idempotent) into
`intermediates/flac/`.

| file | generated by | size |
|---|---|---|
| `intermediates/flac/music.wav` | `gen_wav 12500` (deterministic music-like synth, RF64 container) | 2.2 GB |
| `intermediates/flac/music.flac` | `flac -f -s -8 music.wav` (setup-time encoding) | 1.1 GB |

The generator source is `gen_wav.c` (next to these scripts); the built
binary is an intermediate result in `intermediates/flac/gen_wav`.

## Benchmarks

```bash
work/flac/build-bolt/src/flac/flac -f -s -8 -o /dev/null intermediates/flac/music.wav
#   ~20 s/iter; -8 max compression, output discarded (-o /dev/null)

work/flac/build-bolt/src/flac/flac -d -f -s -c intermediates/flac/music.flac > /dev/null
#   ~8 s/iter; -d decode to stdout, output discarded
```

## Gotchas

* **WAV generator compression ratio.** An early `gen_wav.c` computed
  the note envelope from the *wrapped* note index, so after ~40 s the
  envelope exploded and the signal clipped to full-scale noise (compressed
  to 99% instead of ~48%). It now tracks an unwrapped note index and uses
  a ~1/k^2 harmonic rolloff (like real instruments), which FLAC compresses
  well. (`flac -o /dev/null` works fine, keeping the encode loop
  output-free.)
* **WAV files > 4 GB need RF64.** `gen_wav` emits the RF64 container
  (ds64 chunk, 64-bit sizes) above 4 GB - a uint32 RIFF header would wrap
  and flac would reject the file. Decoding > 4 GB of PCM needs
  `flac -d --force-rf64` (`stream is too big to fit in a single WAVE
  file` otherwise). Sub-gotcha: an earlier RF64 layout had bits-per-sample
  off by two bytes, rejected with `legacy WAVE file has format type 1 but
  bits-per-sample=0`.
* Building `gen_wav.c` with the *system* GNU ld prints `ld: error in
  .../Scrt1.o(.sframe); no .sframe will be created` - a harmless warning
  from GNU ld's own sframe handling (see the `.sframe` gotcha in EXPERIMENT.md).
